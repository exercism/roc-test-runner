# Exercism Roc Test Runner

The Docker image to automatically run tests on Roc solutions submitted to [Exercism].

## Getting started

Build the test runner, conforming to the [Test Runner interface specification](https://github.com/exercism/docs/blob/main/building/tooling/test-runners/interface.md).
Update the files to match your track's needs. At the very least, you'll need to update `bin/run.sh`, `Dockerfile` and the test solutions in the `tests` directory

- Tip: look for `TODO:` comments to point you towards code that need updating
- Tip: look for `OPTIONAL:` comments to point you towards code that _could_ be useful
- Tip: if it proves impossible for the Docker image to work on a read-only filesystem, remove the `--read-only` flag from the `bin/run-in-docker.sh` and `bin/run-tests-in-docker.sh` files.
  We don't yet enforce a read-only file system in production, but we might in the future!

## Run the test runner

To run the tests of a single solution, do the following:

1. Open a terminal in the project's root
2. Run `./bin/run.sh <exercise-slug> <solution-dir> <output-dir>`

Once the test runner has finished, its results will be written to `<output-dir>/results.json`.

## Run the tests

To run the tests to verify the behavior of the test runner, do the following:

1. Open a terminal in the project's root
2. Run `./bin/run-tests.sh`

These are [golden tests][golden] that compare the `results.json` generated by running the current state of the code against the "known good" `tests/<test-name>/expected_results.json`. All files created during the test run itself are discarded.

When you've made modifications to the code that will result in a new "golden" state, you'll need to update the affected `tests/<test-name>/expected_results.json` file(s).

## Dependencies and offline execution

The production container has no network access. `dependencies/packages.roc` declares the shared libraries; each other `.roc` file in `dependencies/` is a small runnable app for one platform. During the image build, `bin/download-dependencies.sh` tests the package declarations and builds and runs each platform app with `--opt=speed`. The pinned Roc compiler caches downloaded dependencies in `/root/.cache/roc/packages`, which is also used at runtime. Separately, `ROC_CACHE_DIR=/tmp/roc` keeps temporary compiler build files on the writable `/tmp` mount; the compiler writes these even with `--no-cache`.

To add a platform, add a smoke-test app under `dependencies/` with its exact release URL. No Dockerfile changes are needed. Add a runner fixture under `tests/` as well. The Docker integration suite runs with `--network none` and a read-only root filesystem to verify that the image is self-contained.

`bin/upgrade-roc-dependencies.sh` updates release URLs across the dependency apps and synchronizes matching URLs in fixtures. After upgrading, rebuild and run the offline suite. In the track repository, run `bin/sync-roc-dependencies.sh /path/to/roc-test-runner` to synchronize the exercise URLs with these declarations.

## Platform test apps

Tests whose app header declares a platform are compiled with `--opt=speed` and executed. Other tests, including library-only `app []` modules, use `roc test`. Header detection ignores comments and strings.

A test app exits with code 0 for success and 1 for failed checks. With roc-parallel, test functions return `Try` values; `main!` collects errors, prints them and a summary through `Stderr.line!`, then returns `Err(Exit(1))`. Other errors returned from `main!` are printed by the platform and also exit with status 1. Other nonzero exits, runtime crashes, and compilation failures are reported as errors. Test apps should include the case description and expected/actual values in failure messages. The runner builds into a temporary directory, so it never writes an executable into the learner's solution directory.
